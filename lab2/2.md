# 实验二：软件设计与建模

## 一、 实验目的
+ 掌握面向对象的设计方法
+ 熟练使用UML图描述面向对象的设计思路
+ 掌握UI设计工具的使用方法


## 二、 实验内容
+ 根据实验一中完成的需求分析报告，使用UML图描述软件的整体架构，要求写明软件的模块划分（必须包含实验一中的基本要求模块），以及各模块之间的交互
   + 这里，我们将UML图分为三类，分别为
     +  结构性图（静态图）：主要分析和描述系统或流程的结构，包括：类图、对象图、组件图、复合结构图、部署图、包图和剖面图
     +  行为性图（动态图）：主要描述系统的行为、它的参与者和它的构建组件，包括：活动图、用例图、状态图
     +  交互性图： 通信图、交互概览图、时序图、序列图
   + 其中，类图为必画图，在此基础上，请了解并掌握上述每一种UML图，并在三类中每一类至少挑选一种你认为合适你项目的UML图，进行绘制展示。也就是说，你的报告内应该至少有**四种**UML图，请记得标志他们的名称以区分。
+ 使用UI设计工具为每个功能模块设计UI界面，并辅以必要的文字说明
+ 撰写实验报告

其中，UML图需要使用[PlantUML](https://plantuml.com/zh/)绘制，UI设计工具可以使用亿图图示等绘制工具。

+ 在本次实验中，允许你自由使用大模型之类的工具，选择你认为合适的场景辅助进行软件设计，但**请注意以下事项**：
  + 大模型等工具只是辅助作用，我们要求你必须有自己的思考和判断，不可以完全地依赖。例如，你可以让它帮忙给出一个UML用例图的PlantUML样例代码，或者是某种UI控件可能的设计方案，再以此为基础进行修改，完善。
  + 请在实验报告的一个单独章节中详细描述你使用这些辅助工具的过程，要求包括自己的思考，修改优化的过程，并对该辅助工具的优缺点进行分析。
    + 每一次使用都需要记录，必要的内容包括：使用场景，生成结果，优缺点分析，修改优化后的结果。
    + 在该章节的结尾我们希望你能从自己的体验出发，尝试思考总结一下，大模型这类工具可以如何辅助软件设计。
+ 最重要的是，实验报告的书写**不允许使用大模型的辅助**！

## 五、 常见问题以及提醒

+ 这个项目需要最终完整运行吗？
  + 此时选择的项目会覆盖整个学期的课程，在学期结束的时候我们希望得到一个500行以上的原型（基本结构完整，设计清晰，可供后续工程师完成系统搭建），但具体细节可以留作TODO。因此，在设计时请尽可能保证基本功能的完备性，包括数据的存储形式等。
+ 请在实验报告中首先清晰地说明，自己选择的项目。我们鼓励尽可能完备的设计，美观的，实用的设计会获得额外的分数。
+ 后续实现的时候和实验二的设计有冲突怎么办？
  + 实验二的设计和实验三的实现不一致是没有关系的，并且这也是正常现象。理论上来说应该依据最新的实现修改设计，但后续不作要求，不过鼓励大家在后续实现时更新实验二的设计。
